# 题二 · 拍摄指南（手机 + 显示器屏幕方案）

> 本文对应「在另一显示屏上全屏显示棋盘格」这条路径（题二原文允许）。
> 与打印方案的区别只有一处：**方格边长必须实测，不能填标称值**。
> 剩下的坑更多，所以单独成文。

---

## 0. 先看清这条路的风险

打印方案是"漫反射的纸"，屏幕方案是"自发光的像素阵列"。三个差别会真实影响标定结果：

| 差异 | 后果 | 本指南的对策 |
|---|---|---|
| 屏幕是**像素网格** | 相机采样屏幕像素会产生摩尔纹，角点定位精度下降 | 拉远、避开正对、提高屏幕亮度 |
| 方格尺寸取决于**屏幕 PPI** | 不知道真实边长，测距会整体比例错误 | 直尺量 10 格 ÷ 10，传给 `--square` |
| 手机 ISP 可能**自动做几何矫正** | 畸变系数被"吃掉"，`k1` 接近 0，去畸变对比图看不出差别 | 用主摄 1x、不用超广角；尽量存 RAW |

第三条最要命。题二基本要求 12 分里有一项是「**去畸变效果正确**」，如果你的标定结果 `k1 ≈ 0`，那张前后对比图就是两张一模一样的图 —— 这一项拿不到分。

**如果手机有 RAW / DNG 选项，一定要用。** RAW 不经 ISP 矫正，畸变是真实的。没有 RAW 的话，至少做到：只用主摄（1x），不碰 0.5x/0.6x 超广角，关掉"镜头畸变矫正"开关（部分安卓机有）。

## 1. 准备屏幕

### 1.1 生成满屏版棋盘格

```powershell
cd D:\rm-vision-recruit-brj
.venv\Scripts\python.exe q2_calib\gen_chessboard.py --screen
```

脚本会读取当前显示器分辨率，生成 `q2_calib/board/chessboard_9x6_screen_1920x1200.png`。

**关键：图片分辨率必须等于显示器原生分辨率。** 否则浏览器/看图软件缩放会引入非整数采样，格子边缘发虚。

### 1.2 显示要求

1. 用**浏览器**打开这个 png（不要用 Windows 照片应用，它的缩放行为不可控）
2. 按 **F11** 全屏
3. **确认比例没被拉伸** —— 肉眼看格子应该是正方形。如果变成长方形了，说明显示被拉伸，换方式

> 浏览器默认会保持长宽比缩放，所以就算有缩放（比如浏览器工具栏占掉一点高度），格子仍是正方形，只是变小了 —— 这没关系，**用尺量出来的值才是准的**。

### 1.3 屏幕设置

| 项目 | 设置 | 原因 |
|---|---|---|
| 亮度 | **调到最高** | 压低手机 ISO，减少噪点 |
| 夜间模式 / 护眼 | **关掉** | 色温偏移会让黑白对比下降 |
| 对比度增强 / 动态对比 | **关掉** | 会自动压黑格边缘，改变边缘位置 |
| 清晰度 / 锐化增强 | **关掉** | 制造假的边缘，让角点定位偏移 |
| 反射 | 关掉顶灯、拉上窗帘，手机屏幕避开窗户 | 玻璃反光斑会直接盖住角点 |

### 1.4 ⭐ 实测方格边长（原文硬要求）

拿一把直尺，**贴着屏幕**，从第 1 个格子的左边缘量到第 11 个格子的左边缘（即 10 个格子的总长），除以 10。

```
例：10 格共 305 mm  →  单格 30.5 mm  →  标定时 --square 30.5
```

**为什么量 10 格而不是 1 格**：直尺读数的误差是 ±0.5 mm 左右。量 1 格，相对误差 1.7%；量 10 格再除以 10，相对误差降到 0.17%。这个差异会直接体现在测距精度上 —— 3 m 处，1.7% 就是 5 cm 误差。

**把量出来的数字记在纸上，别靠记忆。**

## 2. 准备手机

### 2.1 相机设置

| 项目 | 设置 | 原因 |
|---|---|---|
| 镜头 | **1x 主摄** | 超广角畸变被 ISP 矫正得最狠，`k1` 会趋近 0 |
| 格式 | **RAW / DNG**（有就用） | 不经 ISP 几何矫正 |
| 分辨率 | 最大即可 | 后面会被缩到长边 1600，先拍大一点有冗余 |
| 变焦 | **绝对不要用数码变焦** | 裁切+插值，等于人为制造模糊 |
| 对焦 | 点屏幕对棋盘中心一次，锁定（长按屏幕通常能锁 AF/AE） | 连拍时焦点漂移会让部分图变糊 |
| 闪光灯 | **关** | 屏幕反光 |
| HDR | **关** | 多帧合成会移动边缘 |
| 美颜 / 滤镜 | **关** | 会做局部平滑，破坏角点 |

### 2.2 手要稳

屏幕拍糊是最常见的废图原因。手机靠在桌沿/书上，或者两只手肘撑在桌上。

## 3. 拍 20 张标定图

**核心思路：屏幕不动，手机动。** 标定只关心"相机与棋盘的相对位姿"，谁移动都一样。

把棋盘摆在你正前方约 0.5 m，然后按下面的顺序拍。**每拍一张就在纸上打个勾**，别靠回忆。

| 组 | 张数 | 怎么拍 |
|---|---|---|
| A 正对（不同距离） | 5 | 手机正对屏幕中心，距离 0.3 / 0.4 / 0.5 / 0.6 / 0.8 m 各一张 |
| B 左右倾斜 | 4 | 手机绕竖直轴转 30°~45°，左偏 2 张、右偏 2 张 |
| C 上下倾斜 | 4 | 手机绕水平轴俯仰 30°~45°，上仰 2 张、下俯 2 张 |
| D 绕光轴旋转 | 4 | 手机本身转 15°~45°（画面里的棋盘是斜的），四个方向各一张 |
| E 角落构图 | 4 | 棋盘出现在画面**左上 / 右上 / 左下 / 右下**，各一张 |

**E 组不能省。** 畸变系数（`k1`、`k2`）全靠画面边缘的角点数据才能解出来。如果 20 张全把棋盘放正中间，标定出来的畸变会接近 0，你的去畸变对比图就看不出任何变化 —— 那 12 分里的"去畸变效果正确"直接没了。

> 屏幕方案的 E 组要点：**手机离屏幕近一点、往侧后方退**，让棋盘落在画面角落，而不是把棋盘挪到屏幕角落（屏幕上挪不动，而且棋盘必须完整入镜）。

### 拍完立刻检查

```powershell
# 1) 手机照片传到 q2_calib/phone_raw/（见第 5 节）
# 2) 批量检查
.venv\Scripts\python.exe q2_calib\check_images.py
```

脚本会打印每张图的检出情况，并在 `q2_calib/q2_figs/corner_check.png` 生成一张拼图 —— **绿角点=可用，红叉=废图**。

它同时会把转正、缩小后的副本写进 `q2_calib/calib_images/`，标定直接读这个目录。

**检出不来的图要重拍，不要硬凑。** 20 张里剩 16 张也够（原文要求 15~25）。

## 4. 拍 5 组测距图（A4 纸）

这一组和标定无关，是给 `solvePnP` 用的。

| 要求 | 说明 |
|---|---|
| 目标 | 一张 A4 纸（210 × 297 mm），白纸即可，**四个角要看得清** |
| 距离 | 0.5 / 1.0 / 1.5 / 2.0 / 3.0 m，至少 5 组 |
| 姿态 | A4 纸**正对**手机镜头，别歪（歪了测的是斜距） |
| **卷尺入镜** | ⭐ 每张照片里都要能看到卷尺的读数 |

**卷尺这条是原文「说明」里的硬要求**：「测量照片中宜包含卷尺等实测依据」。没有卷尺的照片，无法证明这个距离是你真量过的。

摆法：卷尺从手机镜头所在位置拉到 A4 纸下沿，让刻度正对镜头能看清。

> ⚠️ 很多人拍到第 5 组才想起来卷尺，前面全得重拍。**从第一组就摆好。**

## 5. 照片怎么传（这一步有坑）

**别用微信直接发。** 微信即使选"原图"，某些情况下仍会重编码。用下面两种方式之一：

**A. 数据线（最稳）**
手机连电脑 → 资源管理器里打开手机 → `DCIM/Camera/` → 全选拖到 `D:\rm-vision-recruit-brj\q2_calib\phone_raw\`

**B. 微信「文件传输助手」→ 必须勾选「原图」**
发送时勾"原图"，电脑端保存后确认文件大小是 MB 级（不是几百 KB 的缩略图）。

## 6. 完整命令序列

```powershell
cd D:\rm-vision-recruit-brj

# ① 生成满屏棋盘格
.venv\Scripts\python.exe q2_calib\gen_chessboard.py --screen

# ② 照片放进 q2_calib\phone_raw\ 之后：批量检查 + 转正 + 缩小
.venv\Scripts\python.exe q2_calib\check_images.py

# ③ 看 corner_check.png，把 FAIL 的重拍，重跑 ②

# ④ 标定（--square 填你直尺量出来的值，本项目实测为 25.0）
.venv\Scripts\python.exe q2_calib\calibrate.py --square 25
```

**跑完先看重投影误差。** 经验判据：

| RMS | 判断 |
|---|---|
| < 0.5 px | 很好 |
| 0.5 ~ 1.0 px | 可用，个别图偏差大可以剔掉重跑 |
| > 1.0 px | **先别往下做**，回头看 `calibrate.py` 标出的偏大那几张，大概率是边缘畸变严重或轻微模糊 |

## 7. 屏幕方案的额外收益（可以写进报告）

做完之后，你手上会有一个**打印方案不会产生的观察**：

> 屏幕上显示的棋盘格，其方格边长由显示器 PPI 决定，与"18 mm"的标称值无关。实测值若与标称值差异明显，说明标定的 `--square` 必须用实测值 —— 这本身就是对"标定依赖真实物理尺度"这一点的直接验证。

另外，屏幕是**平面**但并非绝对平面（尤其笔记本屏有轻微弯曲），且存在像素网格。如果标定得到的畸变系数比预期小很多，除了手机 ISP 矫正之外，也可以检查一下：**是不是所有图都拍得太正、棋盘占画面比例太小**。

## 8. 检查清单

拍之前逐条对一遍：

- [ ] 棋盘格是**原生分辨率**满屏显示，格子是正方形
- [ ] 屏幕亮度最高、护眼/锐化/动态对比全关
- [ ] 顶灯关了，屏幕没有反光斑
- [ ] **直尺量了 10 格总长，记下数字**
- [ ] 手机用 1x 主摄，数码变焦归 1.0，HDR/美颜关掉
- [ ] 20 张按 A~E 五组拍完，E 组（角落）没漏
- [ ] 5 组测距图，每组**卷尺入镜**
- [ ] 照片用数据线或"原图"传到 `q2_calib/phone_raw/`
- [ ] `check_images.py` 跑过，FAIL 的已重拍
